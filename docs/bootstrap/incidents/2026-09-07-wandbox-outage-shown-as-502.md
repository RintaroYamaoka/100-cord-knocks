# 2026-09-07 — Wandbox 全体障害が「実行サービスがエラーを返しました」(502) で見えていた

## 何が起きたか

利用者から「エラーが出ている」と報告。本番で Rust 以外の 6 言語
(Python / C++ / C# / Java / TypeScript / JavaScript) を実行すると、どのコードでも
`502 {"error":"実行サービスがエラーを返しました"}` になっていた。Rust (Playground) は正常。

Wandbox に直接投げると、**どのコンパイラでも、User-Agent を変えても** 同じ 500 が返った:

```
Error: Failed to get uid: status=exit status: 125, base_dir=/tmp/wandbox/wandbox_20260907_052930_gPiCgf
```

Wandbox のサーバー内でコンテナランタイム (podman) の起動が失敗している状態。
`list.json` (コンパイラ一覧) だけは 200 で生きていた。**こちらのコード・デプロイに
原因はなく、上流の障害。**

## なぜ問題だったか

障害そのものはこちらでは直せない。問題は **見え方** だった。

1. **再試行していなかった** — プロキシは Wandbox の非 2xx を即 502 にしていた。
   再試行していたのは、応答本文に `OCI runtime error` が入る過負荷ケースだけ
2. **メッセージが「何が起きたか」を言っていなかった** — 「実行サービスがエラーを
   返しました」では、自分のコードのせいか、アプリの不具合か、上流障害かが
   利用者に区別できない。Rust なら動くことも伝わらない
3. **上流障害は verifier では検出できない** — 問題コンテンツの検証はローカル Docker で
   回している (ADR 0002)。本番の実行先が落ちていても、テストは緑のまま

## 対処

### 直したもの

- `shared::playground::wandbox_http_failure_is_transient(status, body)` を追加。
  5xx、または本文に `Failed to get uid` を含むものを一時障害とみなす。
  4xx (403 の User-Agent 拒否など) は再試行しても直らないので対象外
- `api/execute.rs` の Wandbox 経路で、一時障害なら既存の `WANDBOX_RETRIES` 回
  再試行し、それでも駄目なら **503** と
  「実行サービス (Wandbox) が一時的に停止しています。復旧までお待ちください
  (Rust は影響ありません)」を返す
- 実測した本物の 500 本文をテストの固定値にした (`crates/shared/tests/playground.rs`)

### 直していないもの

- Wandbox が落ちている間、6 言語は実行できない。代替実行先は現状ない
  (ADR 0002 の範囲外)。復旧すれば再デプロイ不要でそのまま動く

### 教訓

- **上流の 5xx は「利用者のコードと無関係」なので、エラーの文言でそう言う。**
  文言に実行先の名前と影響範囲 (Rust は無事) を入れるだけで、問い合わせが
  「壊れた?」から「Wandbox 落ちてる?」に変わる
- **切り分けは「上流に直接投げる」から始める。** プロキシ経由の 502 だけ見ていると
  自分のデプロイを疑って時間を溶かす。コンパイラを変え、User-Agent を変えて
  同じ応答なら上流障害で確定

## 再発防止

- `wandbox_http_failure_is_transient` のテスト 3 件 (実測本文 / 5xx 一般 / 4xx 除外)
- CLAUDE.md の「既知の地雷」に、Wandbox 障害時の切り分け手順を追記
